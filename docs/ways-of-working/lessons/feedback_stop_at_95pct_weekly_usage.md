At about **95% of the account's weekly usage** (all models), the whole chain stops cleanly: each worker finishes or parks its current step, commits and pushes, writes a continued hand-off naming every in-flight run (run ids, leases, heartbeats, servers and PIDs, DB copies), does NOT spawn a successor, and stops; the controller writes its own hand-off and tells Manish (Telegram + session). He then switches to another subscription account and starts a new session with that hand-off. Before that point the tracker (STATE.md, hand-offs, learnings) is kept current at every milestone so a stop at any moment loses nothing. Now in learnlikemagic's principle `docs/principles/dev-workflow.md` §12 (renamed from building-major-features.md 2026-09-28, PR #510) and skill `dev-workflow` B6.

**Refined 2026-10-26** (Manish, codex-factories initiative, verbatim in part: "Don't worry on the usage limits. If we run beyond 95-96%, then I can switch to a different subscription on the same machine … provide those notes to it in such a manner that it can reliably understand everything and reliably take over the complete controller ownership from you"): do not delay a package or wait for the weekly reset because of usage; the ~93% caution only avoids starting a Claude-side step that cannot stop cleanly before 95%. The 95% hand-off is written for a fresh session on a DIFFERENT account: it stands alone (the repo's tracker and briefs; every live run, process, window, PID, port and waiter; what is proven and next; the exact launch line), never resting on this account's remote-control links or session memory; the controller sends the launch line on Attention, and the new controller relaunches the workers from their hand-offs and closes the old windows so nothing runs twice. Codex runs continue through a switch.

**Why:** running into the limit stops every session mid-step at a dialog, work half done and unrecorded (the weekly Fable limit did exactly that on 2026-09-23, [[gotcha_weekly_fable_limit_stops_every_session]]); an account switch needs a complete hand-off.

**How to apply:** read the number with `claude -p "/usage" --output-format text` from any directory (prints "Current week (all models): N% used", the 5-hour session %, per-model weeks; a local command, no model call, ~10 s; a polling loop adds `--no-session-persistence --strict-mcp-config`, so a read leaves no transcript and starts no MCP server, proven 2026-11-05). In learnlikemagic, the address-teacher-feedback watch (`docs/feature-development/address-teacher-feedback/atf-watch.zsh`) polls it every ~10 min and prints each threshold crossed. Warn workers at ~93% (no new long workflow, proof or gate); STOP at 95%. Measured burn on 2026-09-24 with 3 Opus sessions + workflows: ~5 points/hour.
